# Design principles

## 1. Role-aware, not role-confusing

Give learners, creators and affiliates a clear starting point based on their tasks. Shared navigation and components should behave consistently, while role-specific tools should remain focused.

## 2. Clarity before decoration

Visual hierarchy should make the page purpose, primary action, status and next step easy to understand. Motion and visual effects should support comprehension rather than compete with it.

## 3. Feedback at every meaningful step

Forms, uploads, purchases, bookings and publishing actions need clear progress, success and error feedback. Never make a user guess whether an action worked.

## 4. Design the full state model

For each important screen, consider:
- Default state
- Loading state
- Empty state
- Validation state
- Error state
- Success state
- Offline or retry state
- Permission-denied state

## 5. Mobile is a first-class context

Prioritise readable type, comfortable touch targets, sensible content order and practical navigation at small widths. Avoid simply shrinking desktop layouts.

## 6. Accessibility is part of quality

Use semantic structure, keyboard-operable controls, visible focus, appropriate labels, sufficient contrast and reduced-motion support.

## 7. Trust is a design requirement

Prices, fees, commissions, balances, payout states, account access and data usage must be explained accurately. Never imply that a simulated action is a real transaction.
